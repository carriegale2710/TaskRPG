# Step 2: Habit Done check

Set up one QuickAdd Macro choice named `TaskRPG: Habit Done` with user script `Scripts/habit-done.js`. Enable its lightning-bolt command. Open `Engine/Habits/Morning routine.md`, invoke that QuickAdd command, and choose on time or late based on your real habit block. A Meta Bind button can run the choice: use Meta Bind's button builder to select the QuickAdd command (copy its actual command ID with `Meta Bind: Select and copy command id`); do not guess an ID. The QuickAdd command itself works as the fallback button.

After a press inspect the one-line notice, `Engine/Events.md`, the habit's History and the Meta Bind fields in `Engine/Hero.md`. Keep `Campaign/00 Hero.md` for stable identity only. The event log is authoritative; the habit history and hero note are displays. Settings and engine rules are unchanged. Do not press again if a notice says the event was saved but updating a display failed: repair from the log first. Only one device should write to the log at a time; merge Fit conflicts before further presses.

On desktop, verify on-time and late presses against the engine result; check that there is no dice roll or story beat. Repeat on phone after syncing files and QuickAdd configuration. Record device, plugin versions, notice text, log line, HP/MP/XP, and any error; mobile behavior has not been validated. If the phone macro fails, use desktop to log a catch-up press with the correct time/status only after reviewing the event history; do not manufacture a past timestamp or silently double-count. This is a manual-validation gate before issue #3.
